# Ads Kill — Android prototype 0.1.0-beta1

**Independent app**, no AI Orchestrator runtime, account, subscription, or remote AIVEXUS infrastructure.

## Scope

- Android 10+ (API 29), built for Galaxy S24 FE tests.
- Android VpnService intercepts **DNS traffic only** to virtual resolver `10.88.0.2`, not general web traffic.
- First offline blocklist: 19 domain suffixes, including DoubleClick, Unity Ads, AppLovin and Vungle.
- Allowed DNS queries are forwarded with protected UDP sockets to **Cloudflare DNS 1.1.1.1 / 1.0.0.1**. The app does not operate an upstream resolver.
- Live counters; foreground notification; manual start/stop; 60-second global allow-all window for reward-ad experiments.
- No HTTPS/TLS decryption, root, accessibility service, traffic capture, analytics, or personal-data upload.

## Install and test

1. Download `ads-kill-v0.1.0-beta1-debug.apk` from the pre-release / the Android workflow artifacts.
2. Allow installation from your chosen file manager on your own test device.
3. Launch **Ads Kill**; select **Avvia protezione**; approve the standard Android VPN consent.
4. Browse a regular website to verify DNS still works; then test a game with ads.
5. For a rewarded ad, tap **Consenti pubblicità per 60 secondi**; try the game's reward; protection resumes on its own.
6. If connectivity fails, immediately select **Disattiva protezione** in Ads Kill or disconnect its VPN in Android settings.

The 60-second window applies to **all** DNS requests. It is not app-scoped yet. Apps which cache DNS, pin hardcoded IPs, use built-in DoH/DoT, or receive ads from same first-party domains may bypass filtering. Reward ads are NOT guaranteed to work during the window. Android permits one active VPN per user/profile, so Ads Kill conflicts with other VPNs.

The Android debug signing key is generated by the CI runner and **not stable across builds**. To update a later prototype you may need to uninstall this one first; it has no user accounts or user records to migrate.

## Build from source

```sh
cd ads-kill/android
gradle assembleDebug
```

Requires JDK 17, Android SDK API 35, Gradle 8.10.2. The CI workflow installs these and uploads a debug APK.

## Architecture, risks, and future work

The first prototype is intentionally small. No ad-evasion promises: YouTube video-stream ads cannot generally be removed by DNS-only filtering. No Windows implementation is included yet. Test startup, DNS resolution, foreground operation, data connection changes, restart/revoke behavior and 60-second unblocking on a **real device** before treating it as stable.

Priority next: fix device findings, add signed-beta update path, per-app controls, Windows DNS filtering service, optional filter-list updates with trustworthy provenance, richer diagnostics without leaking queries, IPv6 / Private DNS handling.

## Android 0.1.1 beta 1 — Smart Reward experimental

- A new optional setting suggests an ad allowance only when **WeWard** (package `com.weward`) appears to be the foreground application and a known ad DNS domain is blocked.
- First enable **Suggerisci la pausa con un popup**, then separately grant "Display over other apps" and "Usage access" in Android settings using the two buttons in Ads Kill. Nothing is collected or transmitted; Ads Kill only compares the foreground package to WeWard locally.
- When triggered, a small overlay appears for about 7 seconds, with **Continua blocco** or **Consenti 60 s**. Suggestions are rate-limited to one every 3 minutes.
- The signal is **heuristic**, not proof of a rewarded ad; a normal ad or analytics request can trigger it, and some rewarded ads may be missed entirely (DNS caching, DoH, foreground detection).
- The allowance remains **global** and time-limited. After approving an allowance, tap the reward ad in WeWard again; the app may need to retry DNS.
- This beta still **cannot block YouTube native-app preroll ads**, which are typically delivered from shared content infrastructure.
- This build is signed using a different ephemeral GitHub Actions debug keystore than the previous beta. If Android says package conflicts, **uninstall the previous Ads Kill beta first**; this resets counters and VPN/permission settings, but does not affect WeWard.
- If no popup appears, check permissions and Smart Reward switch. If internet breaks, disable the VPN.


## Android 0.1.2 beta 1 — remember, block now, signed-only updater

- WeWard popup includes **Ricorda questa scelta per WeWard** (default unchecked). Remembering **Continua blocco** suppresses future suggestions; remembering **Consenti 60 s** allows the next suspected ad window automatically when WeWard is foreground. Because DNS traffic has no reliable requesting-app identity and does not identify rewarded ads, automatic allowances can unintentionally allow regular ads and other apps' ad lookups during the 60-second GLOBAL window.
- A small floating **Blocca ora** button is available during the allowance, as well as a button inside Ads Kill. It cancels the DNS allow window immediately and revokes a remembered automatic allow. **It cannot terminate an ad video already downloaded or an active HTTPS stream.**
- **Dimentica la scelta per WeWard** resets the rule to Ask.
- **Controlla aggiornamenti beta** checks GitHub tags/releases manually. It only offers assets ending `-signed.apk` with SHA256 digest, checks integrity after download, then opens Android's OS installer with explicit user confirmation. No silent updates.
- The GitHub workflow publishes a stable signed APK **only when all four dedicated GitHub repository secrets are configured**: `ADS_KILL_KEYSTORE_BASE64`, `ADS_KILL_STORE_PASSWORD`, `ADS_KILL_KEY_ALIAS`, `ADS_KILL_KEY_PASSWORD`. Never reuse the AIVEXUS production signing key; never commit a private key. Otherwise it emits only an ephemeral debug APK, which **cannot in-place update prior debug builds**.
- Android verifies the new APK certificate matches the existing package. A **one-time uninstall** of the existing ephemeral debug beta is required to migrate to the first persistently signed Ads Kill release. Afterward the same key must be used for all upgrades. This setup is not completed automatically, and the updater may correctly report no signed release yet.
- The update APK is stored in private cache and exposed read-only to Android's installer through a non-exported, temporary-URI-permission provider. User may have to authorize installations from Ads Kill in Android settings.
- All update checks are user-initiated. No background analytics, telemetry or auto-download. GitHub distribution only; review Play Store REQUEST_INSTALL_PACKAGES rules before any Play Store submission.

### 0.1.2 beta2 patch

- The in-app **Blocca ora** action also clears a remembered auto-allow policy, matching the floating stop control. This prevents an immediate 60-second re-allow on the next DNS lookup.
- Version code 4. Unsigned ephemeral debug-key continuity remains unavailable; only dedicated persistent signing enables Android in-place updates.
